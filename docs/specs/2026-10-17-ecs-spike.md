# The ECS spike (1.1.x step B3): the question and the probe

Status: the owner chose "spike first" (2026-10-17 night) over deciding between the
mirror and a full-ECS core on analysis alone (`docs/specs/2026-10-17-actors-as-entities-decision.md`).
A throwaway branch, `ecs-spike`; nothing from it merges except this file's results.

## The question

What does the core cost and look like with the actors stored as `bevy_ecs` entities,
byte-exact in lockstep? Measured, not predicted: build time, run time, the code's shape at
the call sites, and what an idiomatic ECS family looks like beside today's.

## The probe

1. Baseline on `buttons` (the tip it branches from): a clean release build of `rotj-core`
   (its own target dir, timed), the whole-game chain test in release
   (`the_loop_matches_the_tas_from_stage_1_to_the_ending`, timed), the debug lib tests.
2. Storage: `Slots`' 24 main and 8 second-class slots become 32 entities, spawned once in a
   `bevy_ecs::World` inside `Slots` (`default-features = false, features = ["std"]`),
   each with its `Slot`/`Second` as a component (kind 0 is empty; never despawned). The
   API keeps its shape where Rust allows (`Index`/`IndexMut` over the entities, `iter`,
   `iter_mut`, `len`); slice uses (`main[..16]`) and other sites that cannot keep their
   shape change mechanically, and the count of changed sites is recorded. `Clone`,
   `PartialEq`, `Debug` and `Default` are written by hand (a `World` has none of them).
3. The walk stays the 23-to-0 walk, over the entities.
4. One family, `bobber_spawner`, written idiomatically: its step as a function over
   `&mut World` with queries (the free child slot found by a query over kind, the child's
   components written through the entity), beside today's version, both correct.
5. Proven byte-exact as the port always is: the debug lib tests, the release `--ignored`
   suites (the chain), a 1-seed sweep.
6. Measured again: the same build and chain-test times; the changed-site count; the two
   `bobber_spawner`s side by side.
