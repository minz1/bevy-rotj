Status: approved with changes by the Opus stand-in, 2026-10-17 (applied: the in-scope reads
pre-classified by file:line in the briefs; the shared bank-14 table one field; four proofs of
range; indexes read from the ROM or spawn records proven by a silent test; entries imported
as the handler addresses them; the lo/hi rule tightened; a throwaway per-index check in each
batch; the briefs' rules; `rom_bytes`/`rom_words` and the stomper as the template). Follows
`docs/specs/2026-10-17-behaviour-tables-design.md` (the storage: `prg::Prg`, slice 1 the
hitboxes, released as 1.1.8), from a grep of every `rom_byte`/`rom_word` in
`actor/families/`.

## What this is, and is not

About 250 ROM reads sit in the family files; about 100 of them read a family's own constant
tables: velocities, offsets, timers, turn and knockback tables, spawn positions, CHR and
palette bytes picked by state. These become typed data on `Prg`. Not in scope (they stay
ROM reads, as the HANDOFF says):
- **Metasprite pointers**: any read whose result goes to `work.pointer` or into a
  frame-pointer table the OAM builder walks.
- **Pointer chases**: a `rom_word` whose result is an address read through again
  (`path_platform`'s corners and turns, `waypoint_platform`, the bursts' records,
  `floor_debris`, the stomper's rubble, `final_boss_part`'s death sources).
- Reads outside `families/` (the player, weapons, scripts): slice 3 and later.

The line is blurry inside some families (the stomper's `FRAMES`/`TOUCHES` are pointer
tables read through, yet `waypoint_platform`'s `VELOCITIES` and `path_platform`'s
`$92A7`/`$92AF`/`$92C3` are constants beside its chases; `final_boss`'s `PIECE_X/Y` are
constants inside a metasprite loop), so the orchestrator classifies every read by file:line
before the batches start, and each brief lists its in-scope reads.

## Design

- **Each family with tables gets `pub struct Tables`** in its own file, with named fields
  and `pub(crate) fn import(prg: &[u8]) -> Tables` reading them with `rom_byte`. The
  address consts move into `import` (or stay as consts it uses); handlers no longer call
  `rom_byte` for them.
- **`rom_bytes::<N>(prg, bank, addr)`** in `engine` reads a run of bytes into an array
  (`Hitboxes::import` uses it too; word tables build from it with `from_le_bytes`); a word
  table whose entries overlap (the stomper's `SHIFT + anim` and `+ anim + 1`) is
  `from_fn(|i| rom_word(.., SHIFT + i))`.
- **A table that is a computation goes**: bank 14 `$C5F2`/`$C6F2` (`scenery_spawner`,
  `falling_scenery`, `spike_probe`) is `x << 4` as a 16-bit value (the 6502 has no barrel
  shifter), so its readers shift, and `the_shift_table_is_times_sixteen` pins every entry
  without printing one. Found while porting; it replaces the planned shared field.
- **`families::Tables`** (in `families.rs`, hand-written): one field per family that has
  tables, named as its module, and `import` calling each. `Prg` gains
  `pub families: families::Tables`, imported in `Prg::new`. A handler reads
  `cx.prg.families.stomper.timers[usize::from(body.timer)]`, or binds
  `let tables = &cx.prg.families.stomper;` once. Not generated by `families!`:
  most families have no tables, and an empty `Tables` in each would be boilerplate.
- **Values, not bytes**: a lo table and a hi table become one `[u16; N]` or `[i16; N]`
  when both bytes use the same index and the handler either combines them into one word or
  does a lo op then a same-kind hi op that consumes exactly that carry (`final_boss`'s spot
  offsets): that is a `u16` wrapping op for every input, so no test is needed. The byte
  order comes from the handler (`from_be_bytes`/`from_le_bytes`, `lunging_enemy` keeps the
  hi table first), never from address order. The type is the destination's (`body.vy` is
  `i16`). If the carry is tested or one byte is used alone, the field stays bytes.
- **Entries as the handler addresses them**: a logical index, not a byte offset
  (`final_boss`'s `index * 2` pairs are `[(u8, u8); 5]`); a 4-byte record stride is an array
  of records or pairs (`drift_wave_spawner`'s `+ at`, `+ 1 + at`, `+ 2`, `+ 3`).
- **Names**: fields named for what the value is in the game (`turn_speeds`, `knockback`,
  `spawn_offsets`), the ROM address kept in the field's doc as `(\`$8A6E\`)`.

## The ranges (the rule every family follows)

A table becomes a bounded array only once its index's real range is known. Four proofs
count: every write of the index (slice 1's audit); a guard at the read (`spinner`'s
`timer - 8` under its `timer >= 8` test); a mask (`& 3`); the full `u8` range (a 256-entry
array, or an `abs` bounded by its type). An index that comes from the ROM itself (the
stomper's `anim` from `ANIMS`, `ace_ranger`'s next phase, `path_platform`'s jumps) or from
spawn records (`drift_wave_spawner`'s and `lunging_enemy`'s `subtype`/`behaviour`) is proven
by a test that asserts every source value is below `N` and prints nothing (for spawn
records, over every level's records). Then:
- Size each array to the entries the handler can index, not to a guess at the logical
  table. A read past it (`+ 1` pair reads, `timer & $FE` steps, `+ 3`) is folded into the
  value it really is: a pair read becomes a `u16`/`i16` entry; a read that runs into the
  next table is imported as the bytes it covers, documented as such. One array serves two
  index expressions at the larger size (`final_boss`'s `CHR_RAMP` and `CHR_RAMP + 3 + ..`,
  once `anim`'s bound is traced).
- If an index's range can't be established from its writes (an index lifted from a
  RAM byte other code also writes), the read stays a ROM read and is logged in
  `docs/MODERNIZE.md` as a lead. A bounded array never panics where the ROM would read on.
- The family's `Tables` doc (one line per field) states each index and its range.

## Tests

- No committed test restates the import. The oracle tests don't visit every entry, so each
  batch runs a throwaway check (not committed) that every new field equals the old
  `rom_byte` expression for every index in its range, comparing without printing.
- The range tests above, for ROM- and record-sourced indexes.
- Each family's oracle tests, the Classic suites and the chain; the full set at the end
  (tape tests, a 1-seed sweep, a 300-branch exploration, tapes unchanged).
- `Prg::empty()` builds from a zeroed full-size image (`Prg::new(vec![0; PRG_SIZE])`, a
  named const) so every table
  imports zeros and no `Default` over large arrays is needed.
